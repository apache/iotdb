# TQTS-Bench 端到端 Agent trace 试跑：2026-11-18

本轮已完成固定八题的全部尝试，保存八条完整 DSH 会话和 202 次实际工具调用的输入、输出。七题正常结束，一题在生成中耗尽 token 上限，未交付最终答案。八题原始 gold SQL 均可在服务器执行并返回非空结果。因此，本轮已观察到的问题不能笼统归因于数据未导入或 IoTDB 版本不支持。

这是一轮**带上下文发现的 SQL-agent 探索性采集**，用于寻找后续 cmd/SQL 混合接口可以改进的链路。没有运行 FS 对照组，也不能用其结果声称 FS 优于 SQL。

## 实验设置与边界

- 服务器：`zzy@101.6.42.165`，环境目录 `/data/zzy/iotdb-fs-exp`。
- DSH：`0.1.5-rc.2`；实际模型：`deepseek-official / deepseek-flash`，使用用户授权的现有配置。
- IoTDB：`2.0.11-SNAPSHOT`，Tree 模型，原始 benchmark 公共说明针对 `1.3.3`。
- 固定选题：四个原生 IoTDB 数据包，分别取原始 QA 顺序中的首个 medium 和首个 hard，共八题；在模型运行前冻结，没有按结果换题。
- 初始输入：原始问题、数据库根路径、引擎版本、原生毫秒精度、预算及输出约定。完整 schema 和数据说明不预先注入。
- 模型只可调用 `dataset_context` 和 `iotdb_sql`。前者按需检索原始 `manifest.model_context`，后者提供只读 Tree SQL 与部分 schema 命令。所有八题的工具暴露审计均通过；数据库账号按数据包隔离，跨包读取不可见，写入被拒绝。
- 每题 240 秒，最多准入 30 次工具调用，单条 SQL 45 秒。SQL 返回上限 24,000 字符，公共上下文每页最多 40 个标量条目。超过 30 次的请求会被拒绝，因而调用尝试次数可以超过 30。
- 会话记录中的 `maxTokens=8192` 是单次模型生成上限，不是整题累计 token 上限。
- 本轮未加载此前的 IoTDB SQL skills；原始公共上下文含一定方言说明，但并非完整语言手册。禁止 `SHOW FUNCTIONS` 也是当前工具边界的一项限制。

原始题目和 matching policy 保存在 `selection.json`，配置及输入哈希保存在 `protocol.json`。三个模型侧执行文件的 SHA-256 与冻结值逐一一致。模型运行期间没有修改这些文件。

## 答案复核与 SQL 等价性是两套结果

八题 gold 均成功且非空，行数依次为 `6, 8, 1, 3, 1, 48, 2, 1`。离线执行模型提供的 `final_sql`，使用原始 TQTS matching policy：**0 条直接匹配、5 条结果不等价、1 条执行错误、2 题没有最终 SQL**。

这个 0/8 **不是本轮任务正确率**：

1. **C-MAPSS 030**：最终 SQL 返回 16 个端点，参考返回 8 个窗口变化率。模型答案的八个变化率与参考值最大绝对差约 `4.35e-11`，但 SQL 结果形状不同。
2. **Gas 001**：模型答案给出 `5020520 ms` 和 `-4.39`，与参考一致。最终 SQL 还返回 source time、ordinal、第一传感器等列；官方 matcher 报告无法找到覆盖全部参考和预测列的 pivot binding。
3. **NDBC 005**：答案 `1675516800000 ms`、`2023-02-04 13:20:00 UTC` 和 `20.3 °C` 与参考一致。最终 SQL 同时返回气温和海温，参考只投影目标时间和海温，同样未匹配。答案附注把 `min_time` 误解成最小值对应时间，说明“主答案正确”不代表所有解释都正确。

因此，目前人工逐项复核可确认 **3/8 的最终主答案与参考一致**；另两题与参考语义不一致，三题未完整交付。这是本次八题单次运行的描述性结果，没有独立盲审、重复试验或置信区间，不作为官方 benchmark 分数。

特别需要审计的两处语义：

- **Gas 021**：参考在设备/实验维度保留身份后对窗口排名，前三条都来自 `ethylene_methane`，窗口起点为 `4080000, 3600000, 3720000 ms`。模型把两个实验 pooled 后排名，失去设备身份。题面 “Across both experiments” 也可能引起解释歧义，应在正式评分前审计题面/参考契约。
- **NDBC 028**：参考 M4 输出每小时 `HH:00` 与 `HH:50` 的 gap 样本，共 48 行；模型将 gap 限制为两端均在小时内部，选 `HH:00–HH:10` 与 `HH:40–HH:50`，改变了首次 gap 的时间归属及跨小时边界。它的 gap 数值都是 10 分钟，但这不足以证明时间选择等价。

PVDAQ 006 不使用 stderr 中未交付的思考草稿作为最终答案。它的 gold 返回两个 session，均值为 `60.00006511738033`、`59.90763809908739 Hz`；trace 中相关中间查询已经取得这些值。失败发生在交付阶段。

## 可复用的瓶颈特征

| Trace 特征 | 本轮证据 | 下一轮接口候选 | 需要验证的指标 |
|---|---|---|---|
| 同一路径假设下连续空结果，函数不断变化 | C-MAPSS 013 有 19 次空 SQL 结果；FROM 使用 measurement 路径，反复尝试 count/avg/min/max | 带类型的 device/measurement 引用；空结果附匹配序列数与路径类型；SQL 接口也可获得相同诊断 | 无进展调用数、纠错距离、错误环境归因率 |
| 同一算子反复进行语法变体试错 | C-MAPSS 030 有 9 次错误，包含闭闭窗口和缺少时长单位；PVDAQ 006 多次尝试错误 SESSION 形式 | 受控 window/session 参数、可查询的合法签名、统一时间边界与单位 | 首次有效算子耗时、同类错误次数、结果等价性 |
| 跨实体计算时丢失粒度或身份 | Gas 021 用 GROUP BY LEVEL 池化实验后排名 | 输出保留 entity/window 键；聚合时显式选择 per-entity / pooled；排名可组合 | 实体维度保留率、窗口与排名一致性 |
| 数据已取回，但人工变换与答案展开较长 | C-MAPSS 030 手算窗口变化率；NDBC 028 长篇逐小时展开 | 类型化中间结果可继续执行差分、窗口、排序、投影；结果自带单位/时区 | post-data reasoning tokens、手工计算错误、最终答案大小 |
| 已有可用证据却迟迟不能结束 | PVDAQ 006 取得 session 数值后反复讨论单 SQL 和证据编号，最终 max-tokens | 自动附加 provenance，允许多步任务答案；分离可选 SQL 解释与答案提交 | evidence-ready 到 final 的时间/token、无答案率 |
| 元数据获取过宽或记录被拆散 | 49 次文档检索；三次 SQL 输出截断，其中宽 schema 查询两次 | 按实体返回字段名/含义/单位的完整记录，渐进式展开目录与 schema | 相关字段定位调用数、重复上下文 token、截断率 |

这些是**待检验的接口改进假设**。例如空路径诊断、方言帮助和结果投影也可以改善纯 SQL 工具；没有证据表明它们只能通过 FS 获得。当前公共文档工具按标量扁平化的返回方式本身也可能增加发现成本。

## 下一轮建议

1. 先固定统一的任务答案表示和验证器，同时保留执行等价评分。自动关联实际 call ID，不要求模型重建编号；允许多条 SQL/命令组成一个可核验答案。不要因为输出 SQL 与 gold 形状不同就丢弃正确的多步结果。
2. 将本轮作为开发/验证 trace，不用于最终测试声明。补充独立任务族和重复种子后再评估泛化。对 Gas 021、NDBC 028 先审计粒度、边界及参考解释，不能按某一接口的优势改写题意。
3. 给纯 SQL 与混合组相同的公共语义资料及可检索方言帮助，避免将缺失 skills 或不完备 allowlist 当作 FS 收益。同步固定模型、输出格式、预算和缓存报告口径。
4. 首轮只改动最有证据的命令能力：**类型化路径/空结果诊断、带单位和边界的 window/session、保留实体键的聚合与排名、可继续组合的中间结果**。使用当前 trace 标记无进展段和手工变换段，再用消融区分每项收益。
